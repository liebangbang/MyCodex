## 1. 产品定位

### 1.1 一句话定位

> **MyCodex = 本地优先的 AI 桌面工作台：在保护隐私的前提下，把大模型变成能看、能写、能管多项目的「本机智能助手」。**

### 1.2 它解决的核心痛点

| 痛点（通用） | MyCodex 的回答 |
|---|---|
| 网页聊天不安全 | 敏感文件/对话不出本机，配置本地加密（chmod 600） |
| 网页聊天不连贯 | 多任务管理，关了再开能续上 |
| 网页聊天"不能干活" | 能读本地文件、跑命令、出产物、渲染预览 |
| 单模型不够用 | 多模型路由，文字/视觉按需切 |
| 通用 SaaS 不可改 | 代码开源在你手里，按自己习惯持续定制 |

### 1.3 三大产品价值

1. **本地优先 · 隐私强**：数据留在自己机器，合规风险低。
2. **多模型 · 成本可控**：便宜模型干文字活，视觉模型看图，按需切换。
3. **完全可改 · 为我所用**：从外观到能力都能改，不是被平台框死的黑盒。

## 2. 目标用户

| 用户类型 | 特征 | 易用性要求 |
|---|---|---|
| **主要用户：本机重度 AI 使用者** | 需要在本地用 AI 处理文件/图片/项目的个人（知识工作者、开发者、创作者） | 上手快、功能随手可达 |
| **扩展用户：团队/协作者** | 多人共用模板与知识 | 配置可共享、无需懂代码 |
| **潜在用户：普通职场人** | 想要"私人 AI 助手"但不想折腾 | 零配置、引导式 |

> **易用性目标**：让非技术用户也能在 5 分钟内完成首次有效对话，并逐步发现高级能力——而不是被极客界面劝退。

## 3. 现状能力盘点（产品功能基线）

### 3.1 已实现功能

| 能力 | 状态 | 产品/易用性说明 |
|---|---|---|
| 多模型路由 | ✅ | 按模型名前缀自动选端点（文本/视觉），用户只管选模型 |
| 视觉理解 | ✅ | 多图上传 + OCR 兜底，能识别图片内容 |
| 多任务管理 | ✅ | 新建/切换/删除任务，自动恢复上次任务 |
| 产物预览 | ✅ | 右侧渲染网页/预览文本，URL 可点开；HTML 自动内联资源 |
| 工具执行 | ✅ | 运行命令、读写文件，产物可预览 |
| 视觉主题 | ✅ | 品牌紫色渐变 UI + 真 App 图标 |
| 危险操作确认 | ✅ | 危险命令二次确认，防误操作 |
| 会话存档 | ✅ | 每轮落盘，启动恢复 |
| 完全开源可改 | ✅ | 代码在 GitHub，隐私配置被 .gitignore 拦截 |

### 3.2 技术架构（当前）

```
┌─────────────────────────────────────────────┐
│  前端（JS/HTML/CSS，内联加载绕过 WebKit 缓存） │
│  对话 · 工具卡片 · 产物预览 · 视觉上传          │
└───────────────┬─────────────────────────────┘
                │  pywebview 桥（异步注册 + bootstrap 轮询）
┌───────────────┴─────────────────────────────┐
│  后端（Python · Api 类）                        │
│  _chat_cfg 多模型路由 · _vision_cfg 视觉 · 工具 │
└───────────────┬─────────────────────────────┘
        ┌───────┴────────┐
   ┌────┴────┐      ┌────┴────┐
│  文本模型  │      │  视觉模型 │
└────────────┘      └─────────┘
```

- 运行环境：managed Python 3.13.12 venv（自带 Tk 9.0）
- 配置：`~/.config/mycode/config.json`（chmod 600）
- 数据：`~/.config/mycode/` 下 sessions / logs（被 .gitignore 拦截）

### 3.3 当前主要局限（产品/易用性视角）

1. **仅 macOS**，无 Windows/移动端——覆盖面窄。
2. **无设置中心**：模型切换、密钥、主题散落各处，新用户不知从哪配。
3. **无命令/能力发现**：高级功能（工具、视觉）靠用户"恰好知道"，缺引导。
4. **无首次启动引导**：打开即空白对话，无 onboarding。
5. **知识/上下文靠手动**：想让 AI 长期记住偏好，没有"个人资料"入口。
6. **视觉只"看"不"批处理"**：多图需逐一丢，无批量。
7. **无工作流/定时**：重复动作每次手动触发。
8. **UI 偏极客**：非技术同事有门槛。

## 4. 易用性现状评估

### 4.1 现有 UX 亮点

- 对话/工具/预览三栏清晰，产物直接可见
- 模型切换直观，思考开关、文件图标等控件就手
- 危险操作有确认，安全感好
- 任务自动恢复，不打断心流

### 4.2 易用性痛点（需重点解决）

| 痛点 | 影响 | 严重度 |
|---|---|---|
| 无首次引导 | 新用户面对空界面不知所措 | 高 |
| 高级能力无入口/无发现 | 工具、视觉、模板"用了才知道有" | 高 |
| 配置分散、无设置页 | 改个密钥要翻文件 | 中 |
| 错误提示偏技术 | 报错堆栈吓退普通用户 | 中 |
| 无快捷键/命令面板 | 高频操作鼠标点多步 | 中 |
| 无帮助/文档内嵌 | 遇到问题只能问人 | 中 |
| 视觉与对话割裂 | 传图后流程不连贯 | 低 |

## 5. 产品功能规划路线图

> 稳定性相关（数据一致性、网络重试、安全边界等）见《稳定性需求文档》，本路线图聚焦功能与易用性，二者并行。

### 5.1 总体三阶段

```
V1.x 稳定打磨 ──► V2.0 易用性 + 个性化 ──► V3.0 生态与扩展
（现在）          （重点，3~6 个月）         （愿景）
```

### 5.2 V1.x — 稳定打磨（当前）

**目标**：把基础体验做扎实，没人因为"卡/丢/崩"放弃。

- 巩固对话/视觉/工具/预览/任务恢复
- 完成《稳定性需求文档》P0/P1（数据安全、崩溃自愈、网络容错）
- 统一错误提示语言（去技术堆栈化）

**完成门槛**：数据零串扰、断网可恢复、操作有反馈。

### 5.3 V2.0 — 易用性 + 个性化（重点）

**目标**：让普通用户 5 分钟上手，并能"养成"自己的助手。

| 模块 | 关键功能 | 优先级 |
|---|---|---|
| 首次启动引导 | 欢迎页 + 密钥配置 + 示例对话 | P0 |
| 命令面板 | `Cmd/Ctrl+K` 唤起，发现并执行所有能力（模型切换、工具、模板） | P0 |
| 设置中心 | 模型、密钥、主题、语言、默认目录一处可配 | P0 |
| 个人资料/知识底座 | 用户可填"关于我/我的偏好"，生成时自动参考 | P0 |
| 多模态输入升级 | 拖拽即传、粘贴即识别、批量图 | P1 |
| 帮助体系 | 内嵌快捷键表、常见问题、能力说明 | P1 |
| 工作流/定时 | 重复任务自动化（如定时生成草稿） | P2 |

**完成门槛**：新用户首次有效对话 < 5 分钟；任意能力可被命令面板发现。

### 5.4 V3.0 — 生态与扩展（愿景）

| 模块 | 关键功能 |
|---|---|
| 可插拔集成 | 第三方 API/服务以插件形式接入，非硬编码 |
| 模板市场 | 用户共享/导入提示词模板 |
| 跨设备同步 | 配置/知识可选云端（加密）同步 |
| 团队空间 | 共享模板、知识、按角色权限 |

**完成门槛**：非技术用户能装插件、导入模板、零代码扩展。

## 6. 核心功能模块设计（产品/易用性视角）

### 6.1 命令面板（Command Palette）· V2.0 P0

**目的**：解决"高级能力无发现"——把所有功能集中到一个可被搜索的入口。

- 快捷键 `Cmd/Ctrl+K` 唤起，输入即过滤
- 涵盖：切换模型、打开工具、插入模板、打开设置、查看快捷键、搜索历史任务
- 显示每项功能的简短说明与快捷键提示
- 普通用户不必记命令，搜得到就能用

**实现**：前端一个全局 overlay，注册中心来自后端能力清单（便于插件扩展）。

### 6.2 设置中心（Settings）· V2.0 P0

**目的**：把分散配置收拢，新用户一看就懂。

| 分区 | 内容 |
|---|---|
| 模型 | 默认模型、视觉模型、API Key（脱敏显示） |
| 外观 | 主题（亮/暗）、语言 |
| 工作区 | 默认任务目录、文件操作权限（宽松/严格） |
| 关于 | 版本号、诊断包导出、检查更新 |

**实现**：独立设置页（非模态或模态皆可），落盘 config.json，与现有 chmod 600 机制一致。

### 6.3 个人资料 / 知识底座（Personal Context）· V2.0 P0

**目的**：让 AI "长期记得你是谁、你偏好什么"，从单次对话升级为长期助手。

- 用户维护一份 `about_me.md`（身份、偏好、常用术语、禁忌）
- 生成时后端自动注入系统提示词
- 与"可插拔知识"解耦：先整文件注入起步，案例多时升级向量检索

> 这是"为我定制"的产品化表达——不绑定业务，任何用户都能填自己的上下文。

### 6.4 多模态输入升级 · V2.0 P1

**目的**：让"传图/传文件"像聊天一样自然。

| 能力 | 说明 |
|---|---|
| 拖拽即传 | 把图片/文件拖进输入框自动识别 |
| 粘贴即识别 | 截图 Ctrl+V 直接进对话 |
| 批量图 | 一次选多张，按顺序处理 |
| 输入即预览 | 发送前在气泡显示缩略图/文件徽章（已实现雏形，需打磨） |

### 6.5 可插拔工具 / 集成（Extensible Tools）· V3.0

**目的**：第三方能力以插件接入，而非写死在代码。

- 插件描述文件声明：名称、触发命令、所需配置、调用逻辑
- 命令面板自动发现已装插件
- 凭证统一进设置中心，绝不进代码/Git

> 这样"对接某个线上系统"变成装插件，而非改源码——把当前猎帮帮式集成从特例变范式。

### 6.6 工作流与自动化 · V2.0 P2

- 定时任务：本地调度，到点提醒/自动跑（如每日草稿）
- 批量处理：一次丢多文件，逐条跑同一流程，汇总输出

### 6.7 上手引导与帮助体系 · V2.0 P0/P1

- **首次启动**：欢迎页 → 配 Key（或跳过用本地模型）→ 一个示例对话 → 介绍命令面板
- **空状态**：对话区空时显示"试试这些"示例卡片，降低冷启动
- **内嵌帮助**：`?` 打开快捷键表 + 常见问题 + 能力说明
- **错误友好化**：技术错误转为人话 + 下一步建议（如"网络异常，已自动重试"）

## 7. 易用性专项建议

### 7.1 引导与发现

- 首次启动 3 步引导（欢迎 → 配 Key → 示例）
- 命令面板是"能力总入口"，所有功能可搜可达
- 空状态给示例，避免面对空白发呆

### 7.2 配置与反馈

- 设置中心一处配齐，Key 脱敏
- 每个动作有状态反馈（发送中/完成/失败可重试）
- 错误说人话，带"怎么办"

### 7.3 输入与交互

- 拖拽/粘贴即传，批量图
- 全局快捷键（Cmd+K 命令、Cmd+N 新任务等）
- 暗/亮主题切换

### 7.4 学习成本

- 内嵌帮助与常见问题
- 模板/命令带说明，零记忆成本
- 诊断包一键导出，降低求助门槛

## 8. 产品升级迭代建议（按优先级）

### 8.1 P0 — 立即做（易用性底座）

| 建议 | 理由 | 工作量 |
|---|---|---|
| **① 首次启动引导** | 新用户不再面对空界面 | 低 |
| **② 命令面板（Cmd+K）** | 解决能力无发现，所有功能可搜 | 中 |
| **③ 设置中心** | 配置收拢，新用户一看就懂 | 中 |
| **④ 个人资料/知识底座** | "为我定制"的产品化入口 | 低（结构）+ 中（注入） |
| **⑤ 完成稳定性 P0/P1** | 没有稳定底座，易用性无从谈起 | 中（见稳定性文档） |

### 8.2 P1 — 近期（体验跃迁）

| 建议 | 理由 | 工作量 |
|---|---|---|
| **⑥ 多模态输入升级** | 拖拽/粘贴/批量，传图像聊天一样自然 | 中 |
| **⑦ 帮助体系内嵌** | 降低学习成本与求助门槛 | 低 |
| **⑧ 错误友好化** | 技术错误转人话，普通用户不慌 | 低 |
| **⑨ 空状态与示例** | 冷启动不空白 | 低 |

### 8.3 P2 — 远期（生态）

| 建议 | 理由 | 工作量 |
|---|---|---|
| **⑩ 可插拔集成框架** | 第三方能力变插件，非硬编码 | 高 |
| **⑪ 工作流/定时** | 重复动作自动化 | 中 |
| **⑫ 跨设备同步** | 多端配置/知识一致 | 高 |
| **⑬ 模板市场** | 用户共享提示词模板 | 高 |

### 8.4 不建议现在做

- **自研大模型/推理**：用现成模型即可，ROI 低。
- **过早团队版/插件生态**：个人易用性未夯实就扩，易散。
- **Windows/移动端移植**：先 macOS 做深，需求明确再扩。

## 9. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 功能越多越复杂 | 普通用户被劝退 | 命令面板+引导兜底，高级功能默认藏深 |
| 配置错误导致不可用 | 新用户卡在启动 | 启动自检（R-11）+ 配置向导 |
| 插件生态安全 | 恶意插件读文件 | 插件权限声明 + 工作目录白名单（R-03） |
| 维护成本 | 技术债堆积 | 模板/配置与代码解耦，非技术修改不碰代码 |

## 10. 成功指标（易用性 KPI）

| 维度 | 指标 | 目标 |

| 上手 | 首次有效对话耗时 | < 5 分钟（有引导后） |

| 满意 | 错误可理解率 | 技术错误 100% 转人话 |
